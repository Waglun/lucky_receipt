## 1. Описание проекта

«Чек на удачу» — веб-приложение для регистрации и проверки пользовательских чеков в рамках промоакции.

Пользователь может зарегистрироваться, авторизоваться, отправить данные чека и отслеживать статус его проверки в личном кабинете.

Модератор работает с зарегистрированными чеками через стандартную административную панель Django: просматривает данные, изменяет статус и указывает причину отклонения.

## Функционал

### Пользователь

- регистрация и авторизация;
- регистрация чека;
- серверная валидация данных;
- просмотр истории собственных чеков;
- просмотр статуса проверки;
- просмотр причины отклонения;
- пагинация истории чеков.

### Модератор

- работа с чеками через Django Admin;
- фильтрация чеков по статусу;
- поиск по ФН, ФД и ФП;
- изменение статуса чека;
- указание причины отклонения.

### API

- `GET /api/receipts/`;
- проверка авторизации;
- получение чеков текущего пользователя;
- JSON-ответ;
- исключение доступа к чужим чекам.

## API

### Получение чеков пользователя

`GET /api/receipts/`

Endpoint доступен только авторизованным пользователям.

Возвращает чеки текущего пользователя:

```json
[
    {
        "id": 1,
        "fn": "234",
        "fd": "645",
        "fp": "456",
        "purchase_datetime": "2026-10-02T19:30:00+00:00",
        "amount": "1500.00",
        "status": "pending",
        "rejection_reason": "",
        "registered_at": "2026-10-02T14:42:59.014656+00:00"
    }
]
```

## Работа с ИИ

В процессе разработки использовались AI-инструменты как вспомогательный инструмент.

ИИ использовался для:

- обсуждения архитектуры отдельных компонентов;
- поиска и объяснения возможных вариантов реализации;
- помощи при написании отдельных участков HTML/CSS/JavaScript;
- проверки потенциальных ошибок;
- анализа ошибок Django и Docker;
- подготовки и проверки отдельных SQL/ORM решений;
- улучшения структуры и читаемости кода;
- подготовки тестовых сценариев.

ИИ не использовался как полностью автономный разработчик. Предложения проверялись и адаптировались под структуру проекта.

### Ошибки и неточности ИИ

В процессе разработки AI-инструмент несколько раз предлагал решения, которые не соответствовали фактической структуре проекта.

Например:

- была предложена ссылка на `receipts.api_urls`, хотя файл/структура URL требовали дополнительной проверки;
- некоторые HTML/CSS решения первоначально не учитывали существующую структуру `base.html` и подключаемых статических файлов;
- при работе с API требовалось дополнительно проверить, действительно ли параметры запроса могут влиять на выборку данных.

Предложения ИИ проверялись непосредственно в работающем приложении, после чего исправлялись при необходимости.

### Что было бы улучшено при наличии дополнительного времени

- добавить более подробную обработку ошибок API;
